## 2. Security Safeguards & Regulatory Compliance (India)

### 2.1 The Zero-Trust Hybrid Flow (Strictly Enforced)

| Threat / Risk | Vulnerable In-Chat Flow | Carpenterwala Hybrid Secure Flow |
|---|---|---|
| **OTP Leakage & Storage** | User types 6-digit OTP into chat; stored in LLM provider logs and training sets. | **OTP is NEVER handled by the AI.** AI generates an encrypted one-time link. The technician enters the OTP on their phone's secure browser session. |
| **Aadhaar & KYC Document Privacy** | User uploads Aadhaar / PAN to 3rd-party LLM chat (violates UIDAI Aadhaar Act & DPDP Act 2023). | **Government IDs are NEVER uploaded to AI.** Documents are captured in the browser and uploaded directly to encrypted Supabase Storage (`supabase.storage`). |
| **Prompt Injection Attacks** | Malicious prompt tricks AI into leaking session state or other user data. | Server-side stateless tokens are encrypted with `AES-256-CBC/GCM` using server secret key. The LLM cannot read or forge the payload. |
| **Toll Fraud & SMS Spam** | Automated bots call onboarding in a loop. | Enforces a strict sliding limit of **maximum 3 attempts per phone number and IP address per 24 hours**. |

## 3. Active Endpoints & Protocols

### 3.1 Remote WebMCP Server (`/api/mcp`)
- **Transport**: JSON-RPC 2.0 over HTTP POST & Server-Sent Events (SSE) over GET.
- **Protocol Version**: `2024-11-05`
- **Supported Methods**:
  - `initialize`: Returns server info and capabilities.
  - `tools/list`: Lists all 6 tools with complete JSON Schemas.
  - `tools/call`: Executes a tool with arguments.
  - `ping`: Healthcheck.

### 3.2 OpenAPI 3.1 Specification (`/api/mcp/openapi.json`)
- Native schema for Google Gemini (Function Calling, Gemini Extensions) and ChatGPT Custom GPT Actions.
- Exposes direct REST paths for all 6 tools: `/api/mcp/tools/{toolName}`.

### 3.3 AI Session Resolver (`/api/pro/ai-session`)
- Decrypts the 1-click mobile registration token generated by `initiate_technician_onboarding`.
- Safely populates the technician's name, phone, trade, and locality in the Pro Portal registration form.

## 4. Complete Tool Directory (6 Tools)

### 1. `initiate_technician_onboarding`
- **Purpose**: Initiates technician onboarding with 0% platform commission.
- **Inputs**: `name` (string), `phone` (10-digit), `trade` (string), `location` (string), `experienceYears` (number, optional).
- **Rate Limit**: Max 3 calls per 24 hours per phone number.
- **Response**: Encrypted deep link: `https://carpenterwala.com/pro/login?session=...`.

### 2. `check_technician_application_status`
- **Purpose**: Checks verification and review status by phone number.
- **Inputs**: `phone` (10-digit string).
- **Response**: Public status (Verified, Pending Documents, Incomplete) with masked name for privacy.

### 3. `search_verified_pros`
- **Purpose**: Discovers background-checked pros in Bangalore by trade and neighborhood.
- **Inputs**: `trade` (string), `locality` (string, optional), `limit` (number, optional).
- **Response**: List of pros with verified badges, trade, area, and direct profile URLs.

### 4. `get_service_rate_card`
- **Purpose**: Official standard Bangalore labor rate cards (0% commission).
- **Inputs**: `serviceCategory` ("carpentry"|"painting"|"plumbing"|"electrical"), `jobType` (optional).
- **Response**: Transparent labor rates in INR (₹) and estimated job durations.

### 5. `calculate_service_estimate`
- **Purpose**: Instant cost and wastage estimates.
- **Inputs**: `calculatorType` ("paint_cost"|"water_wastage"|"electricity_bill"), `params` (object).
- **Response**: Detailed calculation (e.g., paint liters required, monthly water loss in liters & ₹, monthly electricity units & ₹).

### 6. `request_service_callback`
- **Purpose**: Submits a customer repair lead for 60-90 min rapid dispatch.
- **Inputs**: `customerName`, `customerPhone`, `trade`, `locality`, `description`.
- **Response**: Booking confirmation ID and local dispatch ETA.

## 5. Multi-LLM Testing & Usage Examples

### Example 1: Google Gemini (Android Mobile)
A technician asks Gemini on Android: *"I am a painter in Whitefield, how do I register on Carpenterwala?"*
1. Gemini calls:
   ```json
   POST /api/mcp/tools/initiate_technician_onboarding
   { "name": "Mohan K", "phone": "9845012345", "trade": "painting", "location": "Whitefield" }
   ```
2. Gemini receives:
   ```json
   {
     "success": true,
     "onboardingUrl": "https://carpenterwala.com/pro/login?session=...",
     "instructions": "Tap the secure link to verify your phone and complete registration."
   }
   ```
3. Gemini displays a direct clickable button. Mohan taps it on his phone, the Pro Portal opens with his details pre-filled, sends him the OTP, and lets him snap his ID photo.

```json
      "url": "https://carpenterwala.com/api/mcp"
    }
  }
}
```

`https://carpenterwala.com/api/mcp/openapi.json`
with Authentication: None (Anonymous public access with server-side 24h rate limiting).

## 7. Security Audit & Vulnerability Remediation (Web-Check & Document Handling)

Analysis conducted against [lissy93/web-check](https://github.com/lissy93/web-check) scan vectors and document pipeline:

### 7.1 Web-Check OSINT Findings & Remediation

| Inspection Vector | Initial State | Risk / Issue | Remediated State |
|---|---|---|---|
| **Permissions-Policy** | `camera=(), microphone=(), geolocation=(self)` | `camera=()` completely blocked mobile cameras on modern browsers, preventing technicians from capturing live ID photos during onboarding. | Updated `next.config.mjs` to `camera=(self)` to permit secure client-side document scanning. |
| **Security.txt (RFC 9116)** | Missing `/.well-known/security.txt` | Flagged as missing by web-check and automated vulnerability scanners. | Created `public/.well-known/security.txt` with security contact, canonical URL, and encryption policy. |
| **HTTP Security Headers** | HSTS, CSP, X-Frame-Options, X-Content-Type-Options active | Proper CSP and HSTS preload are in place across all routes. | Maintained strict header configurations. |

### 7.2 Document Handling Vulnerabilities & Remediations

| Vulnerability | Location | Attack Vector / Impact | Remediation Deployed |
|---|---|---|---|
| **Vision API Cost & Memory DoS** | `app/api/pro/verify-doc/route.js` | Attackers could flood endpoint with 50MB+ base64 payloads, exhausting Node.js heap and burning Google Gemini API quotas. | Added **10MB Base64 ceiling** (`413 Payload Too Large`) + sliding **15 scans / hour per IP** rate limiter (`429 Too Many Requests`). |
| **MIME Spoofing / Malicious Uploads** | `app/api/upload/sign/route.js` | Attackers could request signed upload URLs for arbitrary file extensions (`.svg`, `.html`, `.sh`), enabling Stored XSS. | Enforced strict MIME whitelist (`image/jpeg`, `image/png`, `image/webp`, `image/heic`, `application/pdf`). Rejects unauthorized categories. |
| **Unauthenticated Upload URL Flooding** | `app/api/upload/sign/route.js` | Bots could request unlimited signed upload URLs to clutter Supabase storage. | Enforced **25 upload authorizations / hour per IP** sliding rate limit. |
